# Product measurement and experiments

This use case defines measurement and proposal behavior for the hackathon prototype.

- Keep pickup and engagement separate, with each workflow's configured primary and guardrail KPIs.
- Reuse one workflow-scoped cohort object across detection, experiments, proposals and the operator view.
- State minimum sample sizes, stopping rules, comparison corrections and statistical limitations.
- Include an impact score, configuration diff, affected-lead count, evidence and dry run in every proposal.
- Re-evaluate expired or stale proposals against fresh data.
- Learn only from variants that actually ran, and promote winners within their own workflow.
